# Chief Architect reference / Studline feature matrix

Updated October 26, 2026 against the supplied **Chief Architect Premier X18 Reference Manual, August 2026, 1,497 pages**, and the existing Studline source. Page numbers below are printed page numbers (they match the PDF page indices in this attachment). These are original behavioral summaries, not copied implementation, assets or interface artwork.

## Scope and evidence

The requested ranges were extracted and their chapter/subsection organization inspected: Creating Objects 188–204; Positioning 236–251; Editing 252–318; Walls 370–442; Rooms 443–475; Dimensions 476–520; 3D Views 1146–1200; Rendering 1201–1244. Detailed reading focused on the cited behaviors below, with visual checks of wall reference, editing and layer diagrams. This is a capability-level engineering analysis, not a claim to have implemented every menu item or reviewed all 1,497 pages. The separately supplied recording is reviewed in `SCREEN_RECORDING_REVIEW.md`.

The source baseline for this increment is v0.3, commit `6a7ec1f932c630038cc05f6bb26712f6006979f2`. Its existing 109 tests, lint, TypeScript and build passed before changes. Status columns describe **v0.4**, with 131 passing tests and explicit limits. “Implemented” is scoped to the named capability, not product parity. Difficulty: S = localized, M = several modules, L = new geometry/data subsystem, XL = several dependent subsystems.

**Latest user direction:** use whole-wall selection and specification dialogs instead of three face-targeting options. v0.4 deliberately removes the face selector, hover targeting labels and F shortcut; tested reference geometry remains in the core. X18 General/specification organization (423, 464–465) informs original wall/room dialogs; the user specifically requested single-click wall and double-click room activation.

Core evidence: `src/core/{model,geometry,drafting,wallEditing,specifications,materials,rooms,openings,mesh,history,units}.ts`; UI: `PlanCanvas`, `SpecificationDialogs`, `CadMenus`, `Modal`, `Properties`, `ModelView`, `SoftwareModel`; state/storage: `state/store.ts`, `storage/projects.ts`. Test evidence and fresh browser results are in `docs/VERIFICATION.md`.

**Intentional behavioral difference:** X18's wall Length/Angle specification on p.423 describes its own attached-wall behavior. Studline follows this user's instruction to retain shared junctions; enabled orthogonal constraints propagate connected geometry. Rotation is an explicit free-angle operation about A and can tilt adjacent walls. This is documented instead of implying identical behavior.

## Dependency order and next priorities

1. **Current milestone — delivered:** desktop CAD workspace, visible grid/contrast, whole-wall specification, persisted side finishes and room-name/settings dialogs. Precision creation, centered anchored edits and existing geometry/storage remain in place; 131 regression tests and browser checks pass.
2. **Next foundation — highest remaining blocker:** transactional T/X/overlap topology, opening remapping and multi-room face extraction. Professional residential layouts need interior partitions; a single enclosure cannot represent a house plan reliably.
3. **Associative dimensions and wall assemblies:** shared stable reference descriptors must serve dimension objects and layer-based wall references. Introduce explicit migrations, main structural layer and material/finish layers; do not confuse wall classification with construction composition.
4. **Rooms, levels, platforms and elevations:** derive floors/ceilings from valid room polygons, introduce levels and reusable orthographic/section views.
5. **Further systems:** use the chapter-based roadmap in `ROADMAP.md`; verify each geometry system before advanced rendering and takeoffs.
